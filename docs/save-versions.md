# セーブの版の移し替え

セーブの形（`v`）の版と、古い形のセーブを読むときに今の形へ直すしくみ、使えないセーブ（新しい版・壊れたもの）の扱い。コードは `src/save.js`（`readSave` / `SAVE_MIGRATIONS` / `initSave` / `saveProblemText`）。今の形の中身は [save.md](save.md)。

## 版の移し替え（`readSave` / `SAVE_MIGRATIONS`、`src/save.js`）

保存されていたもの（ブラウザ・サーバーのどちらも）は、読むときに `readSave` が今の形（`SAVE_VERSION`）に直してから使う。

- `SAVE_MIGRATIONS[n]` が「形 n → n+1」の直し方。`v` が 1 なら `[1]` → `[2]` → … と 1 版ずつ順に通し、そのたびに `v` を 1 上げる
- 渡されたものはコピー（JSON にして戻したもの）を直すので、もとのもの（`saveStore.cached` やテストで渡したもの）は変わらない。途中でエラーが出たら使えないセーブにする（直しかけのものは使わない・書かない）
- 直したあと、`player` / `progress` / `location` がオブジェクトでなければ使えないセーブ。今はないゾーンにいたセーブは、倒れたときに戻る町のかがり火から始める（直し方ではなく、毎回の読み込みの決まり）
- 直したセーブは、次に保存したとき（`saveGame`）に今の形で書かれる（ブラウザだけにあったものは起動時にサーバーへも今の形で送る）
- `migrateSave(raw)` は使えるセーブか null を返す（`readSave(raw).save`）
- 起動時のデータの確認で、`SAVE_OLDEST` から `SAVE_VERSION` までの直し方がそろっているかを調べる

| 版 | 変えたこと（直し方） |
|---|---|
| v1 | 最初の形 |
| v2 | 衛兵隊長のクエストの id を倒す敵に合わせた（`goblin` → `c_wolf`、`archer` → `c_bee`、`mage` → `c_salamander`、`king` → `c_wolfKing`、`ogre` → `c_golem`、`treant` → `c_treant`、`warlord` → `c_dragon`）。進み具合（`state` / `count`）はそのまま |
| v3 | 覚えたスキルの id の並び `player.knownSkills` を足した。v2 まではレベルで自動で覚えるだけだったので、v2 のころの決まり（衝撃波・ダッシュ・闘気 Lv1、旋風斬 Lv3、メテオ Lv6。直し方の中にそのまま書いてある）で保存したレベルから埋める（Lv5 なら `['shockwave', 'whirlwind', 'dash', 'battleAura']`）。レベルが数でなければ Lv1 として埋める |
| v4 | 回復薬の数 `player.potions` を、道具の数 `player.consumables`（`{ 道具のキー: 数 }`）にした（キーと数はそのまま。今はない道具・上限を超える数は読むとき `applySave` で捨てる・切る）。v1 より前の、数だけのもの（回復薬 `potion` の数）は `{ potion: 数 }` にする。数でもオブジェクトでもなければ `{}` |
| v5 | ステータスが行動で伸びるようになり、潜在 `player.potential` と熟練度 `player.train` を足した。直し方は空のオブジェクトを入れるだけで、読むとき（`applySave`）にはじめの潜在・熟練度 0 で埋める。伸びた値 `base` はそのまま |
| v6 | 熟練度 `player.train` をやめ、伸びた値 `base` を小数で持つようにした。v5 では熟練度 10 で +1 だったので、数の熟練度は `熟練度 / 10` を `base` に足し（直し方の中に 10 がそのまま書いてある）、`train` を消す |
| v7 | さいだいHP・さいだいMP を行動で伸ばすのをやめ、体力・意思・知力（`wis`）・精神力 から計算するようにした。`base.maxHp`（h）は 意思 = h の整数部分の半分（切り捨て）・体力 = 残り（小数も）に分け（37.5 → 体力 19.5・意思 18。一の位までで同じ さいだいHP）、`base.maxMp` は 知力・精神力 の両方に同じ値を入れる（÷ 2 なので同じ さいだいMP）。潜在 `potential.maxHp` は 体力・意思 に、`potential.maxMp` は 知力・精神力 に写す。`maxHp` / `maxMp` は消す |
| v8 | 知力 `wis` をやめ、かしこさ `int` を 知力 と呼ぶようにした（さいだいMP = (int + 精神力) ÷ 2）。`base.spi` に `wis − int` を足して (int + 精神力) を前の (wis + 精神力) と同じにし（Lv1 の値より小さくなれば読むとき `applySave` が Lv1 の値まで上げる）、`base.wis` と `potential.wis` を消す |

## 形を変えるとき（版を足す）

1. `SAVE_VERSION` を 1 上げる
2. `SAVE_MIGRATIONS` に `[前の版]: (d) => { …; return d; }` を 1 つ足す。ない項目があっても落ちないように書き（`d.player` がないなど）、新しい項目には初めの値を入れる。今のデータ（`QUESTS` / `ITEMS` など）は見ない（あとでデータが変わっても同じ結果になるように。直し方の中の古い id などはその版の記録として書いておく）
3. `buildSave` / `applySave` を新しい形に合わせ、上の表と [save-format.md](save-format.md)、`src/save.js` の先頭のコメントを直す
4. テスト（`tests/migrate.test.js`）に、前の版のセーブ（中身をそのまま書いたもの）が今の形に直って読めることを足す（v1 のもの `V1_SAVE`・v2 のもの `V2_SAVE`・v3 のもの `V3_SAVE`・v4 のもの `V4_SAVE`・v5 のもの `V5_SAVE`・v6 のもの `V6_SAVE`・v7 のもの `V7_SAVE` は残しておけば、古い版 → … → 今の形を通して確かめられる）。テストの先頭の `CURRENT`（今の版）も上げる

## 使えないセーブ

| 見つけたもの | 扱い | タイトルに出るもの |
|---|---|---|
| ない | — | 「はじめから」だけ |
| 新しい版のゲームのセーブ（`v` が `SAVE_VERSION` より大きい。どちらか一方でも） | 読まない。もう一方に使えるセーブがあっても使わない（続けると上書きしてしまうため） | 「続きから」を出さず、新しい版で保存されたので読めないことを出す。「はじめから」は確認してから（上書きすることを知らせる） |
| 壊れている・古すぎる（JSON でない、`v` が整数でない、`v` が `SAVE_OLDEST`（1）より小さい、直している途中でエラー、`player` などがない。サーバーのファイルが読めないとき） | 読まない | もう一方に使えるセーブがあれば「続きから」でそれを使い、片方が読めなかったことを出す。なければ読めなかったことを出し、「はじめから」は確認してから |

- タイトルを開いただけでは、どちらのセーブも書き換えない（保存するのは遊び始めてから）
- 使えないブラウザのセーブは、起動時にキー `zankai-turn-save-unread` に写しておく（上書きされても残る）
- サーバーは、形（`v`）の違うセーブ・読めないファイルを置き換えるとき、`saves/save.json.v<形>.bak` / `saves/save.json.unreadable.bak` にも控えを残す（[save.md](save.md) の「サーバー」）。ふつうに古い版から今の版に上がったときも、最初の保存で `save.json.v1.bak`（v2 からなら `save.json.v2.bak`）が残る
- 起動時にサーバーへつながらず、あとでつながったとき（`retryServer`）にサーバーに新しい版のセーブがあったら、サーバーには送らずブラウザだけに保存する
