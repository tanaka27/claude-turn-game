# サーバー（`server.py`）

ローカルサーバーの起動・ゲームのファイルの配り方・セーブの API と、古いタブで新しい進行を上書きしないしくみ。
セーブの中身・いつ保存するか・ブラウザへの保存は [save.md](save.md)。ゲーム側のコードは `src/save.js`。

## 起動と配信

- Python の標準ライブラリだけで動く。`python server.py [ポート] [--open]`（ポートの省略時は環境変数 `PORT`、なければ 8766。`--open` で起動後にブラウザを開く）。自分の PC からだけつながる
- `127.0.0.1`（IPv4）と `::1`（IPv6）の両方で待ち受ける。ブラウザは `localhost` を `::1` から試すので、IPv4 だけだと Windows では断られるまで約 2 秒待たされる。IPv6 が使えない PC では IPv4 だけで動く
- ポートが（IPv4・IPv6 のどちらかで）ほかのプログラムに使われているときは、メッセージを出して終わる。Windows では `SO_REUSEADDR` だと使用中のポートにも入れてしまうため、付けずに `SO_EXCLUSIVEADDRUSE` で確保する
- `start.bat`（Windows）: `PORT`（8766）が使われていないかを `netstat` で確かめてから `server.py %PORT% --open` を起動する。ファイルは UTF-8 で、先頭で `chcp 65001` にしている（Shift_JIS のコンソールでも文字化けしないように）
- ゲームのファイルを配る（キャッシュさせない）。`saves/` の中は配らない。`.css` / `.js` の Content-Type は `Handler.extensions_map` で決めてある（`text/css; charset=utf-8` / `text/javascript; charset=utf-8`。Windows のレジストリの設定で `text/plain` になって読まれないことがないように）。ほかは標準の `mimetypes`

| API | 動き |
|---|---|
| `GET /api/save` | `{"save": セーブ または null}` を返す。ファイルはあるが JSON として読めないときは `{"save": null, "unreadable": true}`（ゲームは「壊れたセーブ」として扱う） |
| `PUT /api/save` | セーブ（とタブの名前 `tab`・読んだときの `base`）を受け取り、下の「古いタブで上書きしない」の決まりで書けるときは書き込み `{"ok": true, "stale": false}` を返す。同じタブの古いセーブ（`savedAt` が今のより小さい）は書き換えず `stale: true`（通信の順番が入れ替わっても古いもので上書きしないため）。ほかのタブのセーブを上書きしそうなときは書かずに 409 `{"conflict": true, "error": …}` |

- 書き込みは一時ファイルに書いてから置き換える。1 つ前のセーブを `saves/save.json.bak` に残す（次の保存で上書きされる）
- 置き換えるセーブの形（`v`）が受け取ったものと違うとき・読めないときは、`saves/save.json.v<形>.bak`（例 `save.json.v1.bak`）/ `saves/save.json.unreadable.bak` にも写す。形が変わったときだけなので、次の保存では上書きされない（新しい版のセーブを古い版のゲームで「はじめから」にしたときや、版が上がったときの控え）。サーバーはセーブの中身を直さない（直すのはゲームの `readSave`）
- 受け付けるのは 512KB までの JSON で、`v`（整数）と `savedAt`（数）を持つものだけ。`base` は書く前に取り除き、`tab` はセーブに残す
- `/api/save` が `{ save: ... }` の形で答えないとき（404 など）は、ゲームはサーバーなしとみなす

- セーブの置き場所は `saves/`。環境変数 `ZANKAI_SAVE_DIR` があればそのフォルダ（ブラウザの通しテスト `tests/e2e/` が一時フォルダにするのに使う。[testing.md](testing.md)）

## 古いタブで上書きしない

同じゲームを 2 つのタブで開くと、古い状態のタブも保存のたびに今の時刻（`savedAt`）を付けるので、時刻だけでは先に進めたタブのセーブを古いタブが上書きしてしまう。ブラウザの `localStorage` もタブどうしで共有しているので、サーバーなしでも同じことが起きる。これを 2 つのしくみで防ぐ。

**1. ほかのタブに知らせる（ブラウザの中。`BroadcastChannel('zankai-turn-save')`）**

- タイトルで「続きから」「はじめから」を押すと `claimSave` が `{ type: 'claim', tab }` を送り、`params.js` の `save.claimWait`（0.2 秒）待ってから、セーブ（ブラウザとサーバー）を読み直す（`initSave`）。タイトルを開いたあとでほかのタブが進めた分も、読み直したセーブから始まる
- 知らせを受けたタブは（タイトルでも遊んでいる最中でも）`blockSaving('otherTab')`: それからは保存しない（ブラウザにもサーバーにも。ページを閉じるときも）。一時停止にして、ほかの画面の上に「保存を止めました」（`#saveBlocked`、`showSaveBlocked`）と「読み込み直す」ボタンを出す。キーも効かない。読み込み直せばまた遊べる（そのタブで始めると、今度はほかのタブが止まる）
- いつも新しく始めたタブが勝つ。`BroadcastChannel` のないブラウザでは何もしない（下の 2 で守る）

**2. サーバーで見分ける（`PUT /api/save`）**

- ゲームはタブごとに名前 `tab`（起動時に作る 16 文字。`saveStore.tab`）を持ち、送るセーブに `tab` と `base` を付ける。`base` はこのタブがサーバーのセーブを読んだとき（起動時・`claimSave`・`retryServer`）の `savedAt`（なければ `null`。`saveStore.serverBase`）
- サーバーは、今のセーブ（`savedAt` が数のもの）があるとき:
  - 今のセーブの `tab` が同じ → 同じタブの続き。`savedAt` が古ければ `stale`、それ以外は書く
  - `tab` が違う（ほかのタブが書いた、または読み込み直した）→ `base` が今のセーブの `savedAt` と同じときだけ書く（このタブが読んだあとにだれも書いていない）。違えば 409
  - 今のセーブがない・読めない・`savedAt` がないときは書く
- 409 を受けたタブは `blockSaving('conflict')`（1 と同じ止め方。文は「サーバーに、別のタブで保存された新しい進行があった」）
- 1 で止めたタブの送信がちょうど届く前に新しいタブが読み直したときは、新しいタブのほうが 409 で止まることがある（読み込み直せば最新から続けられる。進行は失わない）

| 場面 | 結果 |
|---|---|
| タブ A で遊んでいる → タブ B で続きから | A は止まる。B は A の最後のセーブから始まる |
| タブ A を開いたまま、BroadcastChannel の届かないタブ B が続きから遊んで保存 → A が保存 | サーバーは A を 409 にし、A は止まる。B の進行が残る |
| 同じタブの保存の返事が入れ替わって、古いセーブが後から届く | `stale`（書かない） |
| ページを閉じるときの送信（`keepalive`）が前の保存と同時に届く | 同じタブなので、新しいほう（`savedAt` が大きいほう）が残る |
